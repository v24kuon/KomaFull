# 部長組織 用語集・役割境界（1ページ）

部長（bucho）組織の用語と役割を1ページに集約。`bucho.md` / `dentatsu-gakari.mdc` / 各部下エージェントの参照用。

---

## 用語集

| 用語 | 意味 |
|------|------|
| **社長** | ユーザー。最終意思決定者。 |
| **伝達係** | メインのAIアシスタント。社長の指令を部長に渡し、部長の報告を社長に届ける。 |
| **部長** | bucho。招集役兼統合役。部下4名を招集し、意見を集約して社長に報告する。 |
| **部下A/B/C/D** | 技術/業務/リスク/実装の専門家。部長の招集に応じて意見を提出。 |
| **技術参謀A** | 部下Aの別称（bucho-subordinate-architect）。 |
| **業務参謀B** | 部下Bの別称（bucho-subordinate-business）。 |
| **監査参謀C** | 部下Cの別称（bucho-subordinate-risk）。 |
| **実装参謀D** | 部下Dの別称（bucho-subordinate-implementation）。 |
| **親→子→孫→曾孫** | 伝達係（親）→ 部長（子）→ 部下4名（孫）→ 専門サブエージェント（曾孫）の4階層。 |
| **曾孫** | 孫（部下）が Task で起動する専門サブエージェント（explore, verifier, security-reviewer, code-reviewer, test-runner, planner, generalPurpose 等）。起動条件は各部下の .md に従う。**曾孫は孫・曾孫を起動しない**（4階層で止まる）。 |
| **1-Step** | 伝達係が部長を1回だけ起動する現行フロー。旧2-Step（伝達係が部下を直接招集）は廃止。 |
| **Agent ID** | Task 実行時に付与されるUUID。代筆防止・実行証明に必須。 |
| **実行証明ゲート** | 報告前に招集した全員のAgent IDが記載されているかを確認する必須チェック。 |
| **代筆** | 実機を起動せず、他エージェントの意見を捏造すること。厳禁。 |
| **相関ハルシネーション** | 複数エージェントが同一の誤った根拠に基づくこと。クォーラムから除外。 |

## 役割境界

| 役割 | やること | やらないこと |
|------|----------|--------------|
| **伝達係** | 部長を1回起動、報告を無加工で社長に届ける | 部下を直接招集、報告の要約・改変、独断でのファイル操作 |
| **部長** | 部下を招集・集約・報告、実行証明ゲート通過 | 新しい論点の案出し、招集した部下以外の代筆、Agent ID省略 |
| **部下A** | 設計・拡張性・保守性・性能の観点で意見 | 他部下の意見集約、社長への直接回答 |
| **部下B** | 業務フロー・UX・要件整合性の観点で意見 | 同上 |
| **部下C** | セキュリティ・テスト・運用リスクの観点で意見 | 同上 |
| **部下D** | 実装・ルート/認可/DB・検証の観点で意見 | 同上 |
| **曾孫** | 孫（部下）から Task で起動され、専門的な調査・検証を実施 | 部長・伝達係への直接報告、孫・曾孫の起動（深さ制限） |

---

## フロー（単一正本）

```
社長 → 伝達係（部長を1回起動）
         ↓
      部長（重要度判定 → 適応的招集 → 集約 → 実行証明ゲート → 報告）
         ↓
      部下A/B/C/D（並列、観点別プロンプト）
         ↓                ↓（必要に応じて）
         ↓           曾孫（explore / verifier / security-reviewer 等）
         ↓                ↓ 検証結果を部下に返却
      部長（統合報告書）→ 伝達係 → 社長
```

---

## 曾孫起動の制約

- **深さ制限**: 曾孫は孫・曾孫を起動しない。4階層（親→子→孫→曾孫）で止まる。
- **起動条件**: 各部下の `.md` に記載された「曾孫エージェントの起動条件」に該当する場合に限り起動する。
- **無制限連鎖の禁止**: 曾孫がさらに下位エージェントを起動することは仕様上禁止。

## 設計判断・トレードオフ

### 招集責任の委譲（意図的）

**現行設計**: 部下の招集は **部長** が担う。伝達係は部長を1回起動するのみで、部下を直接招集しない。

**経緯**: 旧設計（伝達係が部下を直接招集するフラット構成）では、伝達係が部長に丸投げして組織が停止した（事案 2026-02-03）。その教訓から、部長に Task を付与し「招集・集約」の責務を明示的に委譲する現行設計に移行した。

**トレードオフ**:
- **監視の欠如**: 伝達係は起動された部下の Agent ID を直接記録しない。追跡は部長の報告書（招集階層・実行証明）に依存する。
- **部長失敗時の検知**: 部長の誤招集・捏造は、社長が報告書の「招集階層」「Agent ID」「Task 戻り値原文貼付」を確認することで検証する。伝達係が Step 1 で事前検知する仕組みはない。

**採用理由**: 招集の適応性（重要度に応じた1〜4名）と、部長による一元的な集約責任の明確化を優先した。

---

## 過去の失態と教訓

### 【事案 2026-02-03】丸投げ委譲による機能不全（旧構成時）
- **内容**: 当時は部長に Task がなく、伝達係が部下を招集するフラット構成だった。伝達係が「部下と話し合って」と部長に丸投げしたため、組織が停止した。
- **現状**: 親→子→孫→曾孫の4階層対応により、部長に Task を付与。部長が自ら部下を招集し、部下は必要に応じて曾孫（専門サブエージェント）を起動する。
- **遵守**: 伝達係は部長を1回起動し、「部下を招集して集約せよ」と明確に指示すること。
