# レビュー指摘の検討・対応

## 概要

PR やコードレビューで指摘された内容を受け取り、項目ごとに「対応する / 見送る」を判定する。対応する場合は最小差分で修正し、見送る場合は理由を明示する。複数項目がある場合は 1 件ずつ確認してから結論を出す。修正が不要な項目には編集・テスト追加・ログ更新を行わない。

## 判定ルール

1. 指摘内容が複数含まれる場合、まず項目ごとに分解する
   - ファイルごと、論点ごと、提案ごとに独立した項目として扱う
   - 1つの項目を対応したからといって、他の項目を未確認のまま終了しない

2. 各項目を独立して判定する
   - 妥当な指摘 → 修正を実施する
   - 不要・不適切な指摘 → 理由を説明して見送る
   - 判断に迷う場合 → 実装前に確認する
   - 一部だけ対応し、一部を見送ることを許可する
   - 不要・不適切な項目については、ファイル編集・テスト追加・`.cursor/review-feedback/log.md` 更新を行わない

## 修正時の進め方

1. 最小差分で修正する
   - 既存パターンに合わせる
   - 既存の動作を壊さないことを優先する

2. 検証方法を変更内容に応じて選ぶ
   - 挙動変更、バグ修正、分岐追加 → テスト戦略ルール（`test-strategy.mdc`）に従い、テスト観点表を提示して TDD で進める
   - 軽微な文言修正、コメント修正、アクセシビリティ属性追加、表示のみの微修正 → フル TDD を必須にせず、必要十分な回帰確認を行う

3. 検証は最小スコープで実施する
   - まず関連する単体テスト、Feature テスト、または最小の確認コマンドだけを実行する
   - 必要な場合のみ確認範囲を広げる

4. 修正後の仕上げを行う
   - `vendor/bin/pint --dirty` で整形する
   - 必要条件を満たす場合は `.cursor/review-feedback/log.md` を更新する

## 結果報告

- 各項目ごとに次を明示する
- 判定: 対応した / 見送った / 要確認
- 理由
- 実施内容
- 検証結果

## 注意

- 修正が不要なら編集しない
- テストは常に変更内容に見合う最小スコープから始める
- 指摘に同意できない場合は、技術的根拠を示したうえで意見を述べる
- 複数項目を受け取った場合でも、必ず1件ずつ確認してから結論を出す
